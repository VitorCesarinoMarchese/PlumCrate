# Native CurseForge browser

Mode: Operate. Extend the existing Linux egui app with a CurseForge-style search section. Use the approved Plumbob blue, pale-blue light and charcoal dark theme, original plumbob identity, Settings, local library and reviewed management actions. [DESIGN.md](../../DESIGN.md) defines the current visual system.

Thesis: find Sims 4 mods and custom content on CurseForge inside the app, then inspect provider summaries and screenshots before deciding what to do next.

Own world: Plumbob native theme roles, existing provider page heading, full-width project photos above titles, readable summaries, subdued download/date/category metadata, restrained borders and visible native controls. Photos share the library's 140-point height and centered cover crop. Cards use 12-point corners and keep their padded information body below the image. A filled, full-width Downloads button uses the shared primary colors and a matching download icon, with visible hover and focus outlines. It opens the existing release review directly; clicking the photo or card body opens details. Missing or broken card images show No Preview without shifting titles or actions; static loading cards reserve the same geometry. Provider components retain their existing readable type hierarchy inside the Plumbob shell.

First viewport: Your mods, Discover and Updates in the shared rail or compact top navigation; Discover opens the provider browser with its existing title and The Sims 4 provider label; full-width search field with Search button; Browse by, Category, Game Version and Sort by selectors with labels above; Clear filters; real result count and Previous/Next; a responsive project grid. Filter groups wrap at allocated widths of 180, 260, 142 and 155 points, with 60-point heights and a 104-point clear-action group. Result columns follow the available content width after navigation, using the existing responsive grid. Below 600 points of window height, Filters folds the controls and shows their active count. At 640×480, expanded filters and results share the scroll region below the heading, keeping Clear filters reachable.

Story: save a CurseForge key in local Settings, browse popular projects or search by name, choose a provider content type, category, game version and sort, navigate pages, select a project, read its full summary and view its supplied screenshots. Browse by uses the nine real Sims 4 provider classes: Mods, Create a Sim, Build / Buy, Rooms / Lots, Sims / Households, Pets, Save Files, Worlds and Translations. Category searches full parent paths within the selected type and resets when that type changes. Game Version searches numeric provider versions, newest first. The six sorts are Relevancy, Popularity, Latest update, Date released, Total Downloads and A-Z. Relevancy uses default provider ranking; Date released uses the public API's release-date sort because its API does not expose the website's Creation Date choice. Filter and sort changes restart pagination; Previous/Next retain all submitted dimensions. Clear filters resets type, category and version while retaining search text and sort. A pinned Back to results restores the current page. Escape returns from project details. Ctrl+F returns to browser search. Opening details never launches a website.

Form: code-led native application extension under the user's pinned CurseForge reference. No generated visual assets. Photos, authors, dates, categories, links and counts come only from provider responses. Synthetic data and procedural images are confined to tests and the capture example.

Library state: projects with a consistent, user-confirmed saved CurseForge attachment and matching project ID show a checkmarked View in library button in the selection colors. Disabled mods count independently of local search and On/Off filters. The action reveals the local mod and opens its existing details popup without downloading or changing metadata. Project details show In your library while retaining intentional release downloads. Imports, removal, source changes and game-folder scans refresh the catalog index. Unknown names, unconfirmed attachments, mismatched source URLs and other providers do not count; the UI never guesses a match or claims a release is current.

Constraints: search and inspection remain read-only. Downloads uses the existing browser-assisted installation flow. One confirmation approves the verified release, source, Downloads folder and game destination; the latest eligible release is selected by default. The app then verifies the completed browser download and imports and enables it without further app prompts. Filtering does not download or update mods, write mod metadata, attach sources or save credentials. Download and update actions require user initiation. Images omit Referer. Failed provider detail images hide; failed card images show No Preview. Requests use saved credentials only; unsaved settings drafts do not change provider requests. Search runs on a detached worker with stale-response rejection and coalesced pending requests. The worker loads filter options only when missing or after a failed attempt. Live tests use a local untracked key, without changing the app's saved-Settings requirement.

Finish: inspect native captures, resolve material independent-review findings, document the browser extension, run all repository validation, and verify signed commits if signing succeeds. Existing design files are authoritative; no unrelated drift repair.

Header Activity replaces the permanent bottom status bar. Its count prioritizes undismissed issues, then running tasks, then unread messages; the tooltip reports all three. Compact navigation uses an Activity icon/count and an icon-only appearance toggle. The redundant Local library and CurseForge browser shell labels and scan-duration text are removed; existing heading counts remain.

Activity opens a nonmodal popup anchored to the header with bounded vertical scrolling. Its explicit X uses the existing Clear SVG and has the tooltip and accessibility name Close activity. Outside click, Escape and X close the panel without cancelling work. Running tasks appear first. Browser download import retains its Cancel action, disabled while Installing, and its existing retry flow. Operation history retains scoped Retry and defaults open when an operation has failed.

Brief in-app notifications appear at bottom-right with a 24-point inset, 16-point frame padding, 12-point corners and content width up to 360 points. View activity and Dismiss are explicit actions. Ordinary notices expire after five seconds but remain in session history; reading them in Activity prevents another toast. Repeated identical notices are distinct. Unchanged errors are deduplicated, take priority over routine notices and remain in the foreground until explicitly dismissed. Dismissed errors remain in history. Message history targets 30 entries but never evicts an undismissed error. History is in memory and does not survive restart. Confirmation/review modals suppress both popup and toasts. No operating-system notifications are added.
