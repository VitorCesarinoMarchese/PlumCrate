# Native CurseForge browser

Mode: Operate. Extend the existing Linux egui app with a CurseForge-style search section. Preserve the established charcoal, warm neutral and gold theme, logo, Settings, local library and reviewed management actions.

Thesis: find Sims 4 mods and custom content on CurseForge inside the app, then inspect provider summaries and screenshots before deciding what to do next.

Own world: existing native theme roles, 27-point page heading, compact square project logos, readable summaries, subdued download/date/category metadata, restrained borders and visible native controls. This extends the incumbent system rather than replacing its colors or typography.

First viewport: My mods and Browse mods tabs under the existing logo; Browse mods title and The Sims 4 provider label; full-width search field with Search button; Browse by, Category, Game Version and Sort by selectors with labels above; Clear filters; real result count and Previous/Next; a responsive project grid. Filter groups wrap at allocated widths of 180, 260, 142 and 155 points, with 60-point heights and a 104-point clear-action group. Results have six columns at the user's 1870×1006 size, four at 1200 points and two at 680. Below 600 points of window height, Filters folds the controls and shows their active count. At 640×480, expanded filters and results share the scroll region below the heading, keeping Clear filters reachable.

Story: save a CurseForge key in local Settings, browse popular projects or search by name, choose a provider content type, category, game version and sort, navigate pages, select a project, read its full summary and view its supplied screenshots. Browse by uses the nine real Sims 4 provider classes: Mods, Create a Sim, Build / Buy, Rooms / Lots, Sims / Households, Pets, Save Files, Worlds and Translations. Category searches full parent paths within the selected type and resets when that type changes. Game Version searches numeric provider versions, newest first. The six sorts are Relevancy, Popularity, Latest update, Date released, Total Downloads and A-Z. Relevancy uses default provider ranking; Date released uses the public API's release-date sort because its API does not expose the website's Creation Date choice. Filter and sort changes restart pagination; Previous/Next retain all submitted dimensions. Clear filters resets type, category and version while retaining search text and sort. A pinned Back to results restores the current page. Escape returns from project details. Ctrl+F returns to browser search. Opening details never launches a website.

Form: code-led native application extension under the user's pinned CurseForge reference. No generated visual assets. Photos, authors, dates, categories, links and counts come only from provider responses. Synthetic data and procedural images are confined to tests and the capture example.

Constraints: the current browser supports search and inspection. Filtering does not download or update mods, write mod metadata, attach sources or save credentials. Future download and update actions require user initiation. Images omit Referer and failed provider images hide. Requests use saved credentials only; unsaved settings drafts do not change provider requests. Search runs on a detached worker with stale-response rejection and coalesced pending requests. The worker loads filter options only when missing or after a failed attempt. Live tests use a local untracked key, without changing the app's saved-Settings requirement.
