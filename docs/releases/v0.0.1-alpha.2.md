# v0.0.1-alpha.2

This Linux alpha fixes browser-assisted downloads that could stay at "Waiting for browser download" after browser detection failed.

## Fixes

- If browser detection fails, PlumCrate tries `xdg-open`, then `gio open`. This adds desktop opener fallbacks for sessions such as Hyprland.
- If all launch attempts fail, the download activity shows the error immediately and stops watching the Downloads folder. You can retry after correcting your browser configuration.
- Late launch errors from an earlier attempt cannot fail a newer retry.

## Download and run

Download `plumcrate-0.0.1-alpha.2-x86_64.AppImage` and its `.sha256` file into the same folder, then run:

```sh
sha256sum -c plumcrate-0.0.1-alpha.2-x86_64.AppImage.sha256
chmod +x plumcrate-0.0.1-alpha.2-x86_64.AppImage
./plumcrate-0.0.1-alpha.2-x86_64.AppImage
```

If FUSE is unavailable, use extraction mode:

```sh
APPIMAGE_EXTRACT_AND_RUN=1 ./plumcrate-0.0.1-alpha.2-x86_64.AppImage
```

Install a default web browser and your distribution's desktop URL opener, such as `xdg-utils`. The provider's page may still require a Download or save click. Save the file in the Downloads folder selected in PlumCrate.

Existing mods and settings remain in their current locations. Builds with AppImage update support can check for this release in **Settings → App updates**. Older builds need a manual AppImage replacement.

## Alpha limitations

Linux x86_64 is the release target. CurseForge features require your own API key in local Settings. Start with a small collection and keep backups while testing.

See the [first alpha notes](v0.0.1-alpha.1.md) for the full feature list and other limitations. Report problems at https://github.com/VitorCesarinoMarchese/PlumCrate/issues without API keys or private paths.
